# Research Direction

更新日: 2026-09-09（JST）。現在の主軸はPhase 1。以下は検証すべき研究方向であり、実証済みの研究成果や固定した実装工程ではない。

## Purpose and evidence

既存の軽量LDoS検知器の見逃しを説明し、検知性能と実運用可能な軽量性を両立できるか検証する。既存手法、仮説、観測、支持された結論を分ける。具体的な事実と証拠は [研究ログ](research_log.md)、直近の実装範囲は [Current Phase](current_phase.md) に置く。

既存の [ロードマップ](context/ldos-research-roadmap-2026-09-09.md) は背景資料として保持する。そこにある日付順の工程や数値は、この文書のGate判断や原データ照合の代わりにはしない。ロードマップ中の参照識別子だけでは文献の検証済み根拠とせず、論文等の一次資料を確認してから研究上の主張に用いる。

## Phase 1: Lightweight Temporal-Aware LDoS Detection

既存の軽量LDoS検知器が見逃す通信について、時間構造を表す特徴量の追加により検知性能を改善できるか検証する。問いは「周期性を使えば必ず解決する」ではなく、**既存検知器の見逃しに時間構造の欠落が関係しているか**である。

- 候補: Jain index（バースト間隔の均一性）、Autocorrelation、FFT。候補間の優劣・軽量性は測定で判断する。Jainの高値だけを周期的攻撃の証明にしない。
- 比較: 対象版を固定した既存検知器、単純な閾値等の変更、時間特徴単独、既存検知器＋時間特徴。まず一つずつ追加して寄与を分離する。
- 正常対照: 通常TCPだけでなく、正常周期通信、無選別のランダムバースト、複数フローによる正常輻輳など。可能なら攻撃と平均負荷やTCP性能低下の程度を揃える。
- 評価: Recall、FPR、Precision / F1、Detection latency、Feature calculation cost、CPU / memory cost。混同行列・分母・試行数・未検知数・特徴量の未定義率を併記する。
- TCP goodput、再送等は影響の確認に用いる。分類のみのオフライン評価から、攻撃遮断によるTCP性能回復を主張しない。

### Phase 1 Decision Gates

| Gate | 問い | GO | REVISE / NO-GO |
|---|---|---|---|
| P1-G0 | 対象検知器の版・入力・実行条件と見逃し結果が対応するか | 同定できた対象に限定して原因切り分けへ | 実装差・時刻・ラベルを修正または回収。不足部分は未判定 |
| P1-G1 | 単純な閾値・更新・gate等では説明／改善できない見逃しが残るか | 時間特徴の追加価値を最小比較で検証 | 単純変更で十分ならその方法を評価し、追加特徴は保留 |
| P1-G2 | 厳しい正常条件・独立評価でも時間特徴が有用か | 精度・遅延・計算資源の比較へ | 正常周期の誤検知やjitter依存を記録し、修正／棄却 |
| P1-G3 | 得られる改善に対して追加コストは許容できるか | Phase 1の成果と成立範囲を整理 | 軽量化、対象範囲の限定、方向転換を判断 |

Phase 1だけで有用な成果になれば独立してまとめる。失敗・限界が出てもPhase 2の有効性が証明されたことにはならない。Phase 2へ進む場合は根拠をログに残し、Current Phaseを切り替える。

## Phase 2: Transport-Layer / Congestion-Control Impact-Aware LDoS Detection

「攻撃トラフィックの形そのもの」から発展して、「LDoSによってTCPの回復過程・輻輳制御挙動がどのように崩されるか」を検知信号にできるか検討する。

候補はcwnd、ssthresh、RTT、retransmission、RTO、congestion state、ACK progress、Recovery後から次の損失までの時間、Recovery間に進んだ新規ACK byte数、Recovery / Loss状態滞在率。いずれも採用未決定。TCP variantごとの意味、計測粒度、観測欠落を定義して扱う。

ユーザー提示の研究前提として、passive TCP congestion-control state inferenceにはTCPWN等の既存研究がある。**状態推定そのものを新規性としない。** 新規性候補は「既存のTCP状態推定・transport-layer観測技術をLDoS検知へ利用し、TCPの回復過程や状態遷移異常を検知信号として利用すること」に置く。この利用に研究上の新規性と価値があるかも、実験と一次文献の照合を経て判断する。

### Phase 2 Decision Gates

| Gate | 問い | GOで許可する次の作業 | REVISE / NO-GO |
|---|---|---|---|
| P2-G0 | 内部TCP情報のground truthで、厳しい正常輻輳とLDoSに差があるか | 少数の単純特徴量で分類価値を検証 | 条件・観測を見直すか方向を棄却。推定器には進まない |
| P2-G1 | 単純特徴量で独立評価時の分類価値があるか | Passive observationによる再構成可能性のPoC | 性能低下一般の検知に留まるなら信号を再考 |
| P2-G2 | Passive observationで検知価値を保ったまま再構成できるか | 完成版の検知方式・配置・資源制約を設計 | 直接観測可能なイベントや端末計測へ対象を限定、または中止 |
| P2-G3 | 完成版でも精度・遅延・資源制約を満たすか | 検証した環境の範囲で成果化 | 実装・適用範囲を修正 |

P2-G0/G1の価値確認前にpassive state inference、ML classifier、eBPFによる完成版検知器を実装しない。推定精度の高さだけではLDoS検知への有用性を証明しない。

## Maintenance

研究テーマ、Phase構成、全体仮説が変わったときに更新し、理由と根拠entryを研究ログへ残す。具体的な実験条件や閾値を長期方針として固定しない。
