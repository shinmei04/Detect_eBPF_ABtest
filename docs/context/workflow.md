# 研究の運用

## 役割

- Mac: 実装と実験条件の編集、結果の解析、論文・発表資料の作成。
- GitHub: コード・設定・小さな集計結果の履歴と同期。大量のPCAPや詳細ログは原則入れない。
- 実験用PC: 実験の実行、全実験の生データとログの保存。
- 生データは実験PC以外のディスク等にもバックアップする。バックアップ先・接続先は未設定。

## 手動の実験手順

1. Macの implementation でコードと実験条件を編集する。
2. git status と差分を確認し、対象を明示して commit・pushする。git add . で大量データを誤登録しない。
3. 実験PCで作業ツリーがクリーンか確認してから取得する。共有ブランチなら git pull --ff-only を使う。
4. git rev-parse HEAD で実行コミットを記録し、目的のMac側コミットと一致するか確認する。
5. YYYYMMDD_HHMMSS_条件名 の実験IDを作り、コードの作業場所とは別の runs/<実験ID>/ に保存する。同名なら別IDにする。
6. README.mdへ目的・タイムゾーン付き日時・コミットID・実行コマンド・環境・成否を記録し、実際の条件を保存する。
7. 実験終了後、ログと期待する出力が揃ったか確認する。失敗した実験も残す。
8. Macの results/<実験ID>/ にREADME・設定・summaryを取得する。生データは必要時のみ取得する。
9. 論文に採用した集計データと図は papers/<投稿先>/ 内に固定して保存し、元の実験ID・解析コミットやコマンドを記録する。

実験PCでは原則コードを編集しない。編集した場合はコミットしてpushし、Macへ戻す。
変更を消す reset --hard や、結果を消す clean を同期の手段にしない。
実行中にコードを更新しない。同一環境を使う測定は同時実行しない。

```text
研究用ディレクトリ/

└── runs/                 # Git管理外
    └── <実験ID>/
        ├── README.md
        ├── config.yaml   # 実際に使った設定。既存形式ならその形式で保存
        ├── raw/
        ├── logs/
        └── summary/
```

再解析時は解析コードのコミットとコマンドも記録し、既存の集計を上書きせず別の解析日時のフォルダに保存する。
Macへの取得は実験完了後に行い、実験PCの原本は消さない。ハーネスは今回作らない。

## 結果メモの記入項目

- 実験ID・目的
- 開始日時・終了日時・タイムゾーン
- 実装コミットID、作業ツリーに変更がないこと
- 実行コマンド・実際の設定ファイル
- 実験PC識別名・OS/カーネル・依存関係・ネットワーク構成
- 成功/失敗、出力の検証結果、気付いた点
- 生データの保存場所・バックアップ先
- 解析コードのコミット・解析コマンド
- 使用した論文・図表番号

## Git管理外のファイル

results、manuscript_data、notes、analysis、archive は現時点では親フォルダのGit管理対象ではない。
Mac側も別ディスク等へバックアップする。共通解析を継続開発するときは implementation へ移し履歴管理する。
原稿リポジトリに入れる採用データは少量のCSV等にし、生PCAPは実験IDから辿れるようにする。
